## Context

**Key findings:**
- `FEEDBACK_MASTER_TABLE` exists and captures full execution traces
- The semantic view `DEMANDSENSING_SEMANTIC_MODEL` has **no verified queries yet** — adding them from feedback will directly improve accuracy
- `AGENT_SPEC_BACKUP` stores full agent specs (instructions, tools, models) as VARIANT — we can read/patch these
- `CANONICAL_DATA_FACTS` stores authoritative facts with verification SQL — the pattern for grounding fixes
- Cortex `COMPLETE` function works — we can use it for AI triage classification
- Agents use a stage-based YAML semantic model (`@SEMANTIC_MODEL/DemandSensing_SemanticModel.yaml`)

## Implementation Steps

### Step 1: Create `FEEDBACK_TRIAGE` table
Stores the AI-classified root cause for each negative feedback row:
- `TRIAGE_ID`, `FEEDBACK_ID` (FK), `TRIAGE_CATEGORY` (bad_sql | hallucination | style_tone), `CONFIDENCE`, `ROOT_CAUSE_ANALYSIS` (AI-generated explanation), `TRIAGED_AT`

### Step 2: Create `REMEDIATION_QUEUE` table
Tracks what needs to be fixed and its status:
- `REMEDIATION_ID`, `FEEDBACK_ID`, `TRIAGE_CATEGORY`, `PRIORITY` (critical/high/medium/low), `STATUS` (pending | in_progress | applied | verified | rejected), `ORIGINAL_QUERY`, `FAILED_SQL`, `SUGGESTED_FIX` (VARIANT — holds verified query YAML, instruction patch, or prompt improvement), `FIX_TYPE` (verified_query | instruction_patch | prompt_improvement), `APPLIED_AT`, `VERIFIED_RESULT`, `CREATED_AT`

### Step 3: Create `SP_TRIAGE_NEGATIVE_FEEDBACK` stored procedure
- Reads unprocessed negative feedback (LEFT JOIN where no triage exists)
- For each row, calls `SNOWFLAKE.CORTEX.COMPLETE` with the feedback context (user_query, sql_queries, feedback_reason, response_text)
- AI classifies into one of 3 categories with reasoning
- Inserts into `FEEDBACK_TRIAGE`

### Step 4: Create `SP_GENERATE_REMEDIATION` stored procedure
- Reads triaged but un-remediated feedback
- Based on category:
  - **bad_sql**: Generates a corrected verified query (question + SQL) using Cortex AI + schema awareness
  - **hallucination**: Generates an instruction patch for the relevant agent
  - **style_tone**: Generates a prompt improvement suggestion
- Inserts into `REMEDIATION_QUEUE` with status=pending

### Step 5: Create `SP_APPLY_VERIFIED_QUERY` stored procedure
- Takes a remediation_id, reads the suggested verified query
- Adds it to the semantic view via `ALTER SEMANTIC VIEW ... ADD AI_VERIFIED_QUERIES`
- Updates status to "applied"

### Step 6: Create a monitoring view `V_FEEDBACK_LOOP_DASHBOARD`
- Joins all three tables for a single-pane view of the pipeline status
- Shows: total negative, triaged count, remediation count by status, applied fixes

### Step 7: Seed test data + run demo
- INSERT 3 realistic negative feedback rows (one per category)
- Run the triage procedure
- Run the remediation generation procedure
- Apply one verified query fix
- Re-run the original question to show improvement
