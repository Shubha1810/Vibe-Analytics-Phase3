## Plan: Auto-Apply Instruction Patches to Live Agent

### Context

The agent `INTERACTIVE_DEMANDSENSING_AGENT` is a Snowflake Cortex Agent that can be modified via:
```sql
ALTER AGENT <name> MODIFY LIVE VERSION SET SPECIFICATION = $$...$$
```

The full spec is a JSON object with `instructions.response` and `instructions.orchestration` sections. The spec is ~100KB and includes tools, tool_resources, skills, models, and instructions.

The current spec can be read via `DESCRIBE AGENT` which returns an `agent_spec` column as JSON.

### Implementation: One Procedure

**`SP_APPLY_REMEDIATION`** (update the existing one) — add a branch for `instruction_patch`, `query_optimization`, and `viz_fix` that:

1. Reads the current agent spec via `DESCRIBE AGENT`
2. For `instruction_patch`: Appends the patch text to `instructions.response`
3. For `viz_fix`: Appends a visualization rule to `instructions.orchestration` (viz section)
4. For `query_optimization`: Appends a query hint to `instructions.orchestration`
5. Builds the new spec JSON with the patch injected
6. Runs `ALTER AGENT ... MODIFY LIVE VERSION SET SPECIFICATION`
7. Marks remediation as `applied`

### Key considerations
- The spec is ~100KB — fits within the 100,000 byte limit
- `MODIFY LIVE VERSION` completely replaces the spec, so we MUST include ALL existing fields
- We append to the end of the relevant instruction string (safest — doesn't break existing logic)
- We add a marker comment so future patches are identifiable: `[FEEDBACK_LOOP_PATCH: remediation_id=X]`

### Implementation Steps

1. Update `SP_APPLY_REMEDIATION` to handle all 5 fix types
2. For VQ fixes (`vq_replace`, `vq_add`): keep existing stage-YAML logic
3. For agent fixes (`instruction_patch`, `viz_fix`, `query_optimization`): use ALTER AGENT approach
4. Test with the existing "Poor visualization" remediation in the queue

### Verification
- Run `DESCRIBE AGENT` before and after to confirm instructions were patched
- Ask the same question again to see if duplicated content / viz failure note is gone
- Check `REMEDIATION_QUEUE` shows `status = 'applied'`

### Critical Objects
- `DEMANDSENSING_AI.DEMANDSENSING_SCHEMA.INTERACTIVE_DEMANDSENSING_AGENT` — The live agent to patch
- `SP_APPLY_REMEDIATION` — Procedure to update
