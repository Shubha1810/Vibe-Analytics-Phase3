## Plan: Confidence Gate + Auto-Apply + Pattern Clustering + Comment-Driven Fixes

---

### Context

Currently the feedback loop has 3 manual steps after triage:
1. `CALL SP_GENERATE_REMEDIATION(id)` — manual
2. Review the fix — manual
3. `CALL SP_APPLY_REMEDIATION(id)` — manual

We need to make this **fully automated** while ensuring safety via a confidence gate, and ensure the user's **comment text** directly influences the fix regardless of which chip they selected.

---

### Design: Single Orchestrator Procedure

Instead of 3 separate manual calls, create one master procedure **`SP_FEEDBACK_LOOP_ORCHESTRATOR`** that runs the entire pipeline end-to-end:

```
Triage (already inline) → Generate Fix → Validate Fix → Auto-Apply (if safe) → Log
```

The backend will call this AFTER triage completes, making the full loop instant and autonomous.

---

### Implementation Steps

#### Step 1: Create `SP_VALIDATE_FIX` — The Confidence Gate

For VQ fixes (`vq_replace`, `vq_add`):
- **Compile check**: Run `EXPLAIN` on the generated SQL — if it fails, reject
- **Row check**: Execute the SQL with `LIMIT 1` — if 0 rows, flag as suspicious
- **Comment alignment**: Use Cortex AI to compare the SQL output description against the user's comment (e.g., user said "should be 21%" → check if output contains values near 21%)
- Returns: `PASS` / `FAIL` / `REVIEW_NEEDED` with a confidence score

For agent patches (`instruction_patch`, `viz_fix`, `query_optimization`):
- **Length check**: Patch must be 20-500 chars (not empty, not absurdly long)
- **Relevance check**: Use Cortex to verify the patch addresses the user's specific comment
- Returns: `PASS` / `FAIL`

#### Step 2: Create `SP_FEEDBACK_LOOP_ORCHESTRATOR(P_FEEDBACK_ID)` — The Master Pipeline

This single procedure runs the complete closed loop:

```
1. Check: is this feedback_id already triaged? (it should be, backend does it inline)
2. Generate remediation (calls SP_GENERATE_REMEDIATION)
3. Validate the fix (calls SP_VALIDATE_FIX)
4. Decision gate:
   - If validation = PASS AND priority IN ('critical', 'high') → AUTO-APPLY
   - If validation = PASS AND priority = 'medium' → mark as 'validated_pending_review'
   - If validation = FAIL → mark as 'rejected' with reason
5. If auto-applied → check if comment mentions specific expectations
   (e.g., "should be 21%") and store for regression verification
```

**Comment-driven logic** (applies to ALL categories):
- The user's comment is passed into EVERY AI prompt (already done in SP_GENERATE_REMEDIATION)
- Additionally, for `incomplete_response`: extract specific expectations from comment ("I wanted regional breakdown and recommendations") → generate instruction patch that addresses EXACTLY those gaps
- For `slow_response`: extract the user's perception ("took too long") → optimize the specific SQL that ran
- For `poor_visualization`: extract what was wrong ("duplicated", "wrong chart", "no chart") → generate specific viz rule

#### Step 3: Create `V_FEEDBACK_PATTERN_CLUSTERS` — Pattern Clustering View

A view that groups similar negative feedback using vector similarity:

```sql
-- Groups feedback by semantic similarity of USER_QUERY
-- Shows: cluster theme, count, avg_priority, oldest/newest, status
-- A "cluster" = group of feedback where all queries have ≥0.80 similarity to the cluster centroid
```

Implementation: Use a self-join with `EMBED_TEXT_768` to find feedback pairs with similarity ≥ 0.80, then group by the earliest feedback in each cluster.

#### Step 4: Update `V_FEEDBACK_LOOP_DASHBOARD` — Add cluster + auto-apply metrics

Add columns:
- `auto_applied_count` — fixes applied without human review
- `validation_passed_count` / `validation_failed_count`
- `top_failing_pattern` — the most repeated negative question theme
- `avg_loop_closure_seconds` — time from thumbs-down to fix applied

#### Step 5: Update Backend (`app.py`) — Call Orchestrator After Triage

Change the backend from:
```python
# Current: just triage
CALL SP_TRIAGE_FEEDBACK(id)
```
To:
```python
# New: triage + generate + validate + auto-apply (all in one call)
CALL SP_FEEDBACK_LOOP_ORCHESTRATOR(id)
```

This makes the ENTIRE loop fire on a single thumbs-down click — from feedback to fix in one shot.

### How Each Feedback Type Uses the Comment

| Category | How Comment Drives the Fix |
|----------|---------------------------|
| **Inaccurate data** | Comment like "MAPE should be 21%" → AI uses this as validation target. Generated SQL is tested: does it return ~21%? If yes, PASS. |
| **Didn't answer my question** | Comment like "I need supplier OTIF breakdown" → AI generates VQ specifically for this question pattern, using the comment to understand what data is needed |
| **Incomplete response** | Comment like "Needed regional breakdown and recommendations" → instruction patch explicitly says "For this persona, always include regional breakdown and actionable recommendations" |
| **Slow response** | Comment like "Took 30 seconds, way too slow" → AI analyzes the SQL, suggests optimizations (pre-aggregation, filter pushdown) |
| **Poor visualization** | Comment like "Chart duplicated, showed debug error" → patch says "NEVER duplicate, NEVER expose failures" with the specific failure pattern noted |

### Auto-Apply Decision Matrix

| Priority | Validation | VQ Similarity | Action |
|----------|-----------|---------------|--------|
| critical | PASS | ≥ 0.85 | **AUTO-APPLY immediately** |
| high | PASS | ≥ 0.80 | **AUTO-APPLY immediately** |
| medium | PASS | ≥ 0.75 | Mark `validated_pending_review` |
| any | FAIL | any | Mark `rejected` with reason |
| any | REVIEW_NEEDED | any | Mark `needs_human_review` |

For agent patches (non-VQ): auto-apply is disabled (requires manual agent version publish). They get marked `validated_ready` with the exact text to add.
